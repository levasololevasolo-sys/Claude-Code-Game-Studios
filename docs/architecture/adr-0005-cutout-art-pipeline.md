# ADR-0005: Перекладная анимация персонажей на Skeleton2D

## Status

Accepted

## Date

2026-11-27

## Last Verified

2026-11-27

technical-director; запрос art-director (art bible §5.5, §8); решение делегировано
разработчиком (2026-11-27).

## Summary

Art bible требует «перекладку»: герой и крупные враги собраны из 10–12 отдельных частей,
которые двигаются костями. Решение: сцена-риг на `Skeleton2D` + `Bone2D`, части — жёсткие
`Sprite2D` дети костей, ключи — `AnimationPlayer`; геймплей не знает об анимации, а отдельный
узел `Visual` подбирает анимацию по состоянию героя и подгоняет её длину под тайминги из данных.

## Context

### Problem Statement
100+ одинаковых покадровых рисунков героя нейросетью не получить (каждый кадр чуть другой);
10–12 частей — можно. Тайминги ударов задаются данными (`blade.times`, оружие меняет скорость),
поэтому анимация должна подстраиваться под них, а не наоборот.

### Current State
Герой и чучело рисуются кодом в `_draw()` (временная графика).

## Decision

### Сцена рига (`scenes/characters/hero_rig.tscn`)
```
Visual (Node2D, player_visual.gd)        scale.x = face (разворот)
└─ Body (CanvasGroup, материал flash.gdshader: uniform flash)
   └─ Skeleton2D
      └─ Hip (Bone2D)
         ├─ Torso (Bone2D) ─ Sprite2D torso
         │  ├─ Head (Bone2D) ─ Sprite2D head
         │  ├─ ArmF (Bone2D) ─ ForearmF ─ HandF ─ Weapon (Node2D, сюда вешается сцена оружия)
         │  ├─ ArmB (Bone2D) ─ ForearmB
         │  └─ Cloak1 (Bone2D) ─ Cloak2 ─ Cloak3   плащ — цепочка костей
         ├─ LegF (Bone2D) ─ ShinF
         └─ LegB (Bone2D) ─ ShinB
└─ AnimationPlayer   библиотека hero_anims.res: idle, run, jump, fall, land, roll, dash,
                     strike_1..3, strike_up, strike_down, hurt, flare, death
└─ Smear (AnimatedSprite2D) покадровые смазы оружия — кадры по типу оружия
```

- Части — **жёсткие `Sprite2D`** под костями (без деформации сетки). Деформацию плаща через
  `Polygon2D` с весами добавляем позже, только если цепочки костей мало.
- Порядок слоёв — `z_index` частей (дальняя рука/нога позади тела).
- Масштаб частей (ADR-0004) задаётся **один раз** на `Skeleton2D` (`1/1.5` или `1/3`).
- Белая вспышка при уроне и подсветка — один шейдер на `CanvasGroup` (вся фигура сразу).
- Контур — нарисован в самих частях (дешевле, чем шейдер-контур).
- Свет оберега у бедра — `PointLight2D`, ребёнок кости `Hip` (лимит 16 источников, art bible).

### Связь с геймплеем
- `Player` / `Enemy` **не знают** об анимации. Они выставляют состояние: `face`, `atk_dir`,
  `combo`, `atk_t/atk_dur`, `dash_t/rolling`, `is_on_floor()`, `inv`.
- `PlayerVisual._process()` читает состояние и выбирает анимацию. Для ударов — прогресс
  `k = 1 - atk_t / atk_dur` → `anim.seek(k * length, true)`: анимация всегда длится ровно столько,
  сколько удар по данным, при любом оружии.
- **Хитбоксы — только в коде** (`strike_rect()`), не в анимации. Смаз в анимации — картинка.
- Смаз рисуется по дуге **перед** героем (правило art bible §5.5).

### Импорт
- Фильтр линейный, mipmaps включены (art bible §8). Части одного персонажа — в атласе ≤ 4096².
- Каждый файл — запись в журнале происхождения (art bible §8: источник, лицензия, «ИИ: да/нет»).
- Папки: `assets/art/characters/<имя>/parts/*.png`, `assets/art/fx/smears/<оружие>/`.

### Implementation Guidelines
- Анимации **must** только двигать кости (`position`, `rotation`, `scale`) и `modulate`;
  они **must never** вызывать геймплейные методы (кроме звука шагов через `Events`).
- 2D-IK (`SkeletonModification2D*`) **must not** использоваться.
- Длительность удара **must** приходить из данных; длина анимации — только форма движения.
- Пока частей нет, `_draw()` остаётся; когда риг готов, `_draw()` героя удаляется целиком.

## Alternatives Considered

### Alternative 1: Покадровая анимация (`AnimatedSprite2D`, спрайт-листы)
- **Pros**: проще всего в коде; любой стиль.
- **Cons**: 100+ кадров героя, которые нельзя сделать одинаковыми нейросетью; огромная память;
  каждое новое оружие — новые кадры.
- **Rejection Reason**: art bible §5.5 прямо отвергает.

### Alternative 2: Spine / DragonBones (сторонний плагин)
- **Pros**: профессиональный инструмент перекладки, деформации, IK.
- **Cons**: платная лицензия (Spine), GDExtension под каждую версию Godot — риск с 4.7.1;
  второй инструмент для новичка.
- **Rejection Reason**: встроенных костей достаточно; плагин можно рассмотреть новым ADR.

### Alternative 3: Простая иерархия `Node2D` без `Skeleton2D`
- **Pros**: ещё проще.
- **Cons**: нет кнопок костей и позы покоя в редакторе — анимировать вслепую.
- **Rejection Reason**: `Bone2D` даёт удобство в редакторе почти бесплатно.

## Consequences

### Positive
- Новое оружие = сцена оружия на кости `HandF` + свой смаз, без новых анимаций героя.
- Тайминги баланса не ломают анимацию.

### Negative
- Перекладка выглядит «бумажной», если позы плохие — качество зависит от ключей.
- `CanvasGroup` на каждом враге — лишний проход отрисовки; проверить на 30 врагах.

## Risks
- **Части нейросети не стыкуются в суставах** → рисовать части с запасом-«перехлёстом» у
  суставов (задача art-director / technical-artist).
- **`CanvasGroup` дорогой на 30 врагах** → обычные враги без `CanvasGroup`, вспышка через
  `modulate` на `Skeleton2D`.

## Performance Implications
- **CPU**: `AnimationPlayer` + 12 костей ≈ ничтожно; 30 врагов — проверить профайлером.
- **GPU**: 12 спрайтов из одного атласа → почти один вызов отрисовки на персонажа.
- **Memory**: атлас героя 2× ≤ 4096² (≈ 64 МБ без сжатия, ≈ 16 МБ VRAM-сжатием).
- **Load Time**: незначительно.

## Migration Plan
1. Тестовый риг из прямоугольников-заглушек (без художника), проверить `seek` по прогрессу
   удара и разворот. 2. Заменить заглушки частями героя. 3. Удалить `_draw()` героя.

**Rollback plan**: `Visual` — отдельный узел; можно вернуть `_draw()`, не трогая геймплей.

## Validation Criteria
- Снимки героя во всех позах GDD в `production/qa/evidence/`.
- Удар с `blade.times[0] = 0.24` и с другим оружием (0.4) — анимация заканчивается вместе с ударом.
