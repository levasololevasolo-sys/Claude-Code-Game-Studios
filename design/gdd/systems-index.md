# Навь — список систем игры

> Источник правды по механике: браузерный прототип `prototypes/last-lumen/index.html`
> (все числа — в `prototypes/last-lumen/config.js`). Игра переносится в Godot 4.7.
> Режим студии `modes.workflow: full`: у каждой системы должен быть свой GDD из 8 разделов
> **до** того, как её переносят в Godot.
>
> Важно про версию: на ПК разработчика стоит Godot **4.7.1**. Не использовать ничего, что
> появилось только в 4.7.2 (см. `docs/engine-reference/godot/VERSION.md`).

## Как читать таблицу

- **Слой** — порядок, в котором системы проектируются: Основа → Ядро → Фичи → Подача → Полировка.
- **GDD** — файл документа в `design/gdd/`. «нет» = документа ещё нет.
- **Статус порта** — перенесена ли система в Godot (`src/`).

## Зависимости (кто от кого зависит)

Стрелка «A → B» значит «A нужна, чтобы работала B».

```
Движение и бой (1) ──► Враги (5) ──► Боссы (6)
       │                  │
       │                  ├──► Генерация комнат (10) ──► Забег (11) ──► Сейв-комната
       │                  │
       ├──► Оберег и Вспышка (3) ──► Свет (4)
       │          │
       └──────────┴──► Боги и руны (7) ◄── Двери-развилки (10) дают руны
                              │
Здоровье/щит (2) ◄────────────┘ (Жива даёт щит и лечение)
Враги-элиты (5) ──► Благословения (8)   (Навий витязь — единственный источник)
Враги (5) ──► Оружие и добыча (9)       (дроп оружия с элит и боссов)
Оружие (9) ──► Движение и бой (1)       (тайминги комбо, урон, дальность)
Экономика (12) ◄── Враги (5) (угли), Благословения (8) (Удача)
Экономика (12) ──► База (14) ──► Забег (11)
Сохранение (15) ── нужно Забегу (11), Экономике (12), Базе (14)
HUD (16) читает: здоровье, щит, заряд, руны, благословения
```

Самые «связанные» узлы: `hurtEnemy` (через него идут все множители урона — проклятие, Жар,
Жнец, щит часового) и `applyGod` (через него идут все статусы богов). Их нужно переносить
первыми из ядра, иначе руны и оружие не к чему подключить.

## Порядок переноса в Godot

| Шаг | Что переносим | Почему в этом порядке | Статус |
|---|---|---|---|
| 1 | Движение и бой героя (`src/player/player.gd`) | Всё остальное — про то, как бьёт и двигается герой | **готово** |
| 2 | Здоровье героя, урон по герою, щит, `hurtEnemy` как единая точка урона по врагу | Без единой функции урона нельзя подключить ни статусы, ни оружие | следующий |
| 3 | Враги (4 базовых вида + вес) и Навий витязь | Нужны цели, чтобы проверять бой и статусы | |
| 4 | Оберег и Вспышка + свет и темнота | Главный крючок игры (вопрос прототипа) | |
| 5 | Боги и руны, статусы, экран выбора руны | Строится поверх `hurtEnemy` и Вспышки | |
| 6 | Генерация комнат и двери-развилки | Даёт руны/ресурсы/оружие/баффы как награды | |
| 7 | Забег: локации, ярусы, боссы, сейв-комната | Связывает комнаты в забег | |
| 8 | Оружие и добыча, второй слот | Много контента, но опирается на шаги 1–5 | |
| 9 | Благословения (баффы) | Маленькая система, нужен Навий витязь из шага 3 | |
| 10 | Экономика, Святилище, торговец, база-острог, сохранение | Мета между забегами | |
| 11 | Пепел (сложность после победы) | Нужна готовая победа в забеге | |
| 12 | HUD, звук, сюжет, полировка | Подача поверх готовой механики | |

## Пробелы, найденные при составлении списка

- Нет GDD для: Оберега и Вспышки, боссов, структуры забега, базы, сохранения, HUD, звука.
  Оберег и Вспышка — самый важный из них: это вопрос прототипа и условие закрытия проекта
  («если Вспышка ощущается как кнопка, а не момент, к которому идёшь»).
- `design/registry/entities.yaml` пуст: общие числа (урон удара, длительности статусов, вес
  врагов) пока живут только в `config.js` и самих GDD.
