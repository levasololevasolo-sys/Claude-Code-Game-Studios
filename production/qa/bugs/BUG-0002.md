# Bug Report

## Summary
**Title**: Экраны выбора (руны, бог, итоги) не реагируют на геймпад и мышь — с геймпадом игра встаёт на первом экране
**ID**: BUG-0002
**Severity**: S2-High
**Priority**: P1-Fix this sprint
**Status**: Open
**Reported**: 2026-11-27
**Reporter**: —

## Classification
- **Category**: UI
- **System**: UI экранов выбора (src/ui/rune_offer_screen.gd, god_choice_screen.gd, run_summary_screen.gd)
- **Frequency**: Always (при игре только геймпадом или мышью)
- **Regression**: No

## Environment
- **Build**: рабочая копия 2026-11-27 (git нет), Godot 4.7.2.stable в облачном окружении (у разработчика 4.7.1)
- **Platform**: Linux, xvfb, gl_compatibility (opengl3)
- **Scene/Level**: обычная игра, самое начало забега
- **Game State**: любой

## Reproduction Steps
**Preconditions**: подключён геймпад, клавиатура не трогается.

1. Запустить игру.
2. Открывается выбор руны (дерево на паузе).
3. Нажимать крестовину, A, X, B на геймпаде; щёлкнуть мышью по карточке.

**Expected Result**: карточка выбирается геймпадом (и/или мышью) — InputSetup сам назначает геймпаду jump/strike/interact и крестовину, а мышь — на удар.
**Actual Result**: ничего не происходит: `_unhandled_input` всех трёх экранов читает только InputEventKey по keycode. Игра стоит на паузе, пока не нажать клавишу на клавиатуре.

## Technical Context
- **Likely affected files**: src/ui/rune_offer_screen.gd:33, src/ui/god_choice_screen.gd:28, src/ui/run_summary_screen.gd:23
- **Related systems**: src/core/input_setup.gd
- **Possible root cause**: экраны проверяют коды клавиш, а не действия InputMap (move_left/move_right/strike/interact или ui_*).

## Evidence
- **Logs**: найдено чтением кода (grep по src/ui на InputEventJoypad/is_action — 0 совпадений). Настоящий геймпад в облаке не проверялся.
- **Visual**: production/qa/evidence/qa-2026-11-27/play-start-rune-offer.png — экран, на котором игра встаёт
